# 英訳スパンの表示整形（`backend/display.py`）

## 目的
日本語の文に英語のスパンを埋め込むと、モデルの出力形式（文末ピリオド・文頭大文字）が表示を崩す（`.。` `.、` や文中の大文字。評価レポート §7）。
**表示用の文字列 `display` だけ**を整える。翻訳の採否・原文・保存済みの評価結果には影響しない。

## 契約（変えてはいけないこと）
- 日本語セグメントは `display == text == source`（原文のスライスそのもの）。整形の対象外。
- `assemble()` / `validate_translation()` / `Segment` / 保存済みの評価成果物は変更しない。整形は `assemble()` の**後段**で、`Segment` 列を `DisplaySegment`（`text` = 検証済み訳、`display` = 整形後、`source` = 日本語原文）へ写すだけ。
- 整形後の文字列は、`text` に対して「先頭1文字の大小」と「末尾の単独 `.` 1つ」以外が変わらない。守れなければ `text` をそのまま使う（`format_english` の安全網）。
- 日英の間に空白は挿入しない（スパン外の文字を変えないため）。見た目の余白は CSS のみ。コピーされる文字列は `display` の連結（`joined()`）。
- `outside_preserved()` が偽なら、サービス層は全体を原文に戻す。

## 規則（保守的。不確実なら何もしない）
1. **末尾の `.` を除去**: 次の原文文字が存在し、空白・改行でないとき（`。` `、` や助詞が直後に続く）のみ。除去しない: 略語（Mr. Dr. etc. e.g. vs. Inc. …）、語内に `.` を含む語（U.S. Ph.D.）、単一大文字（J.）、`..` / `…`、末尾が数字や記号 + `.`、`!` `?`。スパンが行末・文末の場合は `.` を残す。
2. **先頭の大文字を小文字化**: 直前の原文が文頭・改行・空白・開き括弧/引用符・`。！？`（閉じ括弧を挟んでも判定）ではなく、先頭語が許可リスト（The, A, He, And, If … 固有名詞になり得ない機能語）にあり、2語目が大文字で始まらないとき（`The Beatles` は触らない）のみ。`I` `I'm` `It's` `A/B` `IT` や固有名詞は触らない。
3. **実行しない**: `...` の扱い、文頭の小文字→大文字化、引用符の変更、スペース挿入、`!`/`?` の除去。誤整形の危険が利点を上回るため。

## 検証
`tests/test_display.py`: 略語・小数・省略記号・固有名詞句・絵文字・結合文字・空文字など 40 件超の表、3000 件のランダム入力（出力は「元・末尾 `.` なし・先頭小文字化・両方」の4通りに限る）、日本語セグメント不変。

## 限界
- 文末の `。` に `!` `?` が続くケース（`!。`）は整形しない。
- `validate_translation` は全角句読点・全角記号を日本語と見なさないため、サービス層（`backend/service.py`）が U+3000–303F / U+FF00–FFEF を含む訳を不採用にする（`validate_translation` 自体は互換性のため変更しない）。
- 整形の効果（Judge 点の変化）は未評価。評価には新しい run が必要で、既存の run は変更しない。
