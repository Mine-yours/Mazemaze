# 運用・保守の手順

自分専用の iPhone アプリを、無料の Apple ID のまま使い続けるための手順です。方針: データは iPhone の中だけ。自動のクラウド同期はしない（バックアップは、手で書き出すファイル）。

## 1. 毎週の入れ直し（署名は 7 日で切れる）
無料の Apple ID で入れたアプリは、**入れてから 7 日で署名が切れ、起動できなくなります**。アプリは自動では削除されず、データも消えません。
- **期限の確認**: 設定 > このアプリについて > 署名の期限。残り 2 日以内になると、ホームの状態の欄に黄色い案内が出ます。
- **入れ直し**: Mac で `ios/Mazemaze.xcodeproj` を開き、iPhone を USB でつないで ▶（Run）。**上書きで入るので、データはそのまま残ります。**
- **やってはいけないこと**: アプリの**削除**（辞書・お気に入り・設定が消えます）。Team や Bundle ID（`jp.mineno.mazemaze`）を変える（別のアプリ扱いになり、データが引き継がれません）。
- 期限が切れて開かなくなったときも、削除せず、そのまま Xcode から ▶ で入れ直します。
- 無料の Apple ID の制限: 1 台に入れられるアプリは 3 つまで、App ID は 10 個まで（Apple の比較表。7 日で失効）。有料の Apple Developer Program にすると、署名が 1 年になります（いまは無料のまま）。

## 2. データの場所と守り方
| データ | 場所 | 備考 |
|---|---|---|
| 辞書（最大 5000 件） | アプリ内 `Application Support/mazemaze-dictionary.json` | 保存は原子的。読めないときは、上書きせずに別名で退避する |
| 辞書の控え | アプリ内 `Application Support/Backups/` | 毎日、最初の起動（または 1 日の最初の復帰）で 1 つ。毎日の分は 8 つ、取り込み・復元の前の分は 3 つまで（別々に数える）。名前の時刻は UTC |
| お気に入り・最近・タブ・設定 | UserDefaults | |
- **バックアップ**（設定 > データ > バックアップと復元）
  - 書き出す: 辞書（意味カード・読んだ文を含む）、お気に入り、翻訳するサイトを 1 つの JSON にして、ファイルアプリ（iCloud Drive を含む）などへ。**月に 1 回程度、または、たくさん保存したあと。**最後に書き出した日が、設定に出ます。30 日たつと、控えめな案内が出ます。
  - 取り込む: 「統合」です。いまあるものは消さず（お気に入りは、40 件の空きの分だけ追加）、同じものは追加しません。意味カードは、モデルが作ったカードと同じ長さ・文字の制限で検査し直します。「翻訳するサイト」は、ログイン・アカウント関連などを除いて追加します（追加されるサイトは、確認画面に出ます）。取り込みは、辞書を保存できて、取り込み前の控えを作れたときだけ行います（途中で止まったら、何も変えません）。壊れた・違う種類・新しい版のファイルは、断ります。
  - 前の状態に戻す: アプリ内の控えから。戻す前の辞書も、控えに残ります。いまの辞書のファイルが読めないとき、控えが壊れている・新しい版のとき、いまの辞書の控えを作れないときは、何も置き換えずに断ります。
- **アプリを削除する前・端末を替える前**: 必ず書き出す。新しい端末で、取り込む。
- 読み込めなかった辞書のファイルは、設定 > バックアップと復元 の下に出ます（共有で取り出せます）。
- iPhone 自体のバックアップ（iCloud / Finder）にも、アプリのデータは含まれます（アプリだけを戻すことはできません）。

## 3. iOS・Xcode を更新したあと（5 分の確認）
Apple Intelligence のモデルは、Apple が時期を決めずに更新することがあります。更新前に、バックアップを書き出しておきます。
1. 設定 > このアプリについて > **エンジンの確認** を、使うエンジンで実行する。**「原文の保持: すべて一致」「エラー 0 件」**であること。英語にできた句の数と平均時間、英語の中身を、前回と比べる（任意で下の表に記録）。
2. Yahoo!ニュースの記事で英語混じりになる。英語をタップで原文。翻訳オフで元に戻る。
3. 単語をタップ → 標準辞書 →「この文での意味（AI）」。保存 → 辞書に入り、意味が入る。
4. 「貼り付けて翻訳」、画像の長押し → 写真に保存、アドレス欄の検索。
5. 問題があれば、`docs/ai/IPHONE_DEVICE_CHECKLIST.md` の該当項目を見る。

## 4. 不具合の調べ方
- 落ちたとき: Mac から、クラッシュログを取り出します（iPhone を USB でつなぐ）。
  ```bash
  xcrun devicectl list devices
  xcrun devicectl device info files --device <名前> --domain-type systemCrashLogs
  xcrun devicectl device copy from --device <名前> --domain-type systemCrashLogs --source <ファイル名> --destination ~/Desktop/
  ```
  ログには、落ちた場所のスタックが入ります（ページの本文は入りません）。
- 辞書の埋め込み表示で落ちたときは、次の起動で自動でボタン方式に戻り、理由が出ます（設定で戻せます）。
- エンジンの問題か、ページの問題かの切り分けには、「エンジンの確認」と「貼り付けて翻訳」を使います。

## 5. ソースの保全・ビルド
- ソース: GitHub（`Mine-yours/Mazemaze`）。`main` = iPhone 単体版、`mac-local-model` = Mac 版（`cef50de`）。リリース相当の区切りには、タグ（`v1.0` など）を付ける。
- ビルド: Xcode 26.1、最低 iOS 18。外部ライブラリなし。ファイルを足したら `python3 ios/tools/generate_project.py`。
- 自動テスト一式: `cd ios/MazemazeCore && swift test` / `node ios/WebTests/run_dom_tests.mjs` / `./ios/scripts/simulator_selftest.sh`（専用のシミュレータ iPhone 17）/ `./ios/scripts/persistence_test.sh`。
- ロジックを意図して変えるときは、Python との一致の正解データを作り直す（`ios/MazemazeCore/Tests/MazemazeCoreTests/Resources/README.md`）。

## 6. 既知の限界（運用で補うもの）
| 限界 | 補い方 |
|---|---|
| 署名が 7 日で切れる | 毎週、Xcode から入れ直す（上書き）。ホームの案内で気づく |
| Apple Intelligence が無害な記事を拒否することがある | その句は日本語のまま。ページを読むのには影響しない |
| モデルの更新で訳が変わる | 更新後に「エンジンの確認」 |
| 辞書の自動同期がない | 手で書き出す |
| 実機の速さ・発熱は未測定 | 使いながら、気づいたことを記録する |
